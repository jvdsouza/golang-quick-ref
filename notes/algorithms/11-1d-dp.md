# 1D dynamic programming

**Recognise it:** "number of ways", "min or max cost", "can you reach", or choices at each step whose sub-answers overlap.
**Core trick:** define `dp[i]` in one sentence, write the **recurrence**, set the **base cases**, and pick an order. If the recurrence only looks back one or two steps, replace the array with two variables.

## Top-down (memoised recursion) template

```go
func solve(n int) int {
    memo := make([]int, n+1)
    for i := range memo {
        memo[i] = -1                       // a sentinel meaning "not computed"
    }
    var f func(i int) int
    f = func(i int) int {
        if i <= 1 {
            return 1                       // base case
        }
        if memo[i] != -1 {
            return memo[i]
        }
        memo[i] = f(i-1) + f(i-2)          // recurrence
        return memo[i]
    }
    return f(n)
}
```

Use a `map[key]int` for sparse or multi-dimensional state, for example `map[[2]int]int`, since arrays work as keys.

## Climbing Stairs

`ways(i) = ways(i-1) + ways(i-2)`, which is Fibonacci.

```go
func climbStairs(n int) int {
    prev, cur := 1, 1                      // ways(0), ways(1)
    for range n - 1 {                      // Go 1.22+ range over int
        prev, cur = cur, prev+cur
    }
    return cur
}
```
O(n) time, O(1) space.

## House Robber

At each house, either skip it (keep the best so far) or rob it (the best from two houses back, plus this one).
`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`

```go
func rob(nums []int) int {
    prev, cur := 0, 0                      // best up to i-2, best up to i-1
    for _, n := range nums {
        prev, cur = cur, max(cur, prev+n)
    }
    return cur
}
```
O(n) time, O(1) space. House Robber II (houses in a circle) runs this twice: once without the first house, once without the last, and takes the max.

## Coin Change (fewest coins)

`dp[a]` = the fewest coins that make amount `a`. `dp[a] = min over coins c of dp[a-c] + 1`.

```go
func coinChange(coins []int, amount int) int {
    const inf = 1 << 31                    // "impossible", large enough to never win a min
    dp := make([]int, amount+1)            // dp[0] = 0 is the zero value
    for a := 1; a <= amount; a++ {
        dp[a] = inf
        for _, c := range coins {
            if c <= a {
                dp[a] = min(dp[a], dp[a-c]+1)
            }
        }
    }
    if dp[amount] >= inf {
        return -1
    }
    return dp[amount]
}
```
O(amount × len(coins)) time, O(amount) space. Greedy (always take the biggest coin) fails. For example, coins `[1,3,4]` with amount 6 gives `4+1+1` instead of `3+3`. Using `inf = 1<<31` instead of `math.MaxInt` keeps `dp[a-c]+1` from overflowing.

## Longest Increasing Subsequence

### O(n²) DP: the one to explain first

`dp[i]` = the length of the LIS **ending at** i.

```go
func lengthOfLIS(nums []int) int {
    dp := make([]int, len(nums))
    best := 0
    for i := range nums {
        dp[i] = 1
        for j := 0; j < i; j++ {
            if nums[j] < nums[i] {
                dp[i] = max(dp[i], dp[j]+1)
            }
        }
        best = max(best, dp[i])
    }
    return best
}
```

### O(n log n): patience sorting with binary search

`tails[k]` = the smallest possible tail of an increasing subsequence of length k+1. The array stays sorted, so you can binary search it.

```go
func lengthOfLISFast(nums []int) int {
    var tails []int
    for _, n := range nums {
        i, _ := slices.BinarySearch(tails, n)   // first index with tails[i] >= n
        if i == len(tails) {
            tails = append(tails, n)            // extends the longest subsequence
        } else {
            tails[i] = n                        // a smaller tail for length i+1
        }
    }
    return len(tails)
}
```
`tails` is **not** the subsequence itself. Only its length is meaningful.

## Recipe

1. **State**: what does `dp[i]` mean? Write it down in one sentence.
2. **Recurrence**: how does `dp[i]` depend on smaller indices?
3. **Base cases**: `dp[0]`, and `dp[1]` if needed.
4. **Order**: fill left to right, so dependencies are computed first.
5. **Answer**: `dp[n]`, `dp[n-1]`, or `max(dp)`?
6. **Optimise space**: if you only look back k steps, keep k variables.

## Takeaways

- Go's zero values often give you `dp[0] = 0` for free.
- Parallel assignment (`prev, cur = cur, prev+cur`) makes rolling variables neat.
- Pick an "infinity" sentinel that can't overflow when you add 1 to it.
